# explorer

## 1. Purpose

`explorer` provides the `Explorer` nodelet, the core of this project's energy-aware UAV coverage planning pipeline. It is the component that actually flies the UAV: it tracks the live octomap and the UAV's current/predicted state, watches for imminent collisions along the predicted trajectory, and periodically assembles a flyable path out of the outputs of the other planning packages. It does not itself solve the travelling-salesman ordering of viewpoints or search the roadmap for collision-free sub-paths — those are delegated at runtime to the standalone `tsp_solver` and `path_planner` nodelets over blocking ROS services — nor does it detect frontiers/viewpoints itself (that's `frontier_detector`). `Explorer`'s own job is to glue these together into a continuously replanned, dynamically-generated trajectory that is handed to the MRS trajectory generator/tracker, while guarding against collisions detected in newer maps.

### Services advertised (server)

| Private name | Remapped to | Type | Handler |
|---|---|---|---|
| `~replan_request_in` | `~replan_request` | `std_srvs/Trigger` | `callbackReplanRequest()` — calls `pathAndTrajectory()` (which calls `makePath()`, then builds and publishes a trajectory) and returns its success/failure as `response.success` (`response.message` is always `"acknowledged"` regardless of outcome) |

`~replan_request_in` and `~replan_request_out` are both remapped in `explorer.launch` to the same private topic `~replan_request`, so this is a synchronous self-call within the `Explorer` node: `requestReplan()` (itself called from `timerReplanner()`) calls its own `~replan_request` service; `callbackReplanRequest()` handles it by running the actual replan (`pathAndTrajectory()` → `makePath()` → `makeTrajectory()` → `publishTrajectory()`) and reporting whether it succeeded. `requestReplan()` uses that result to move `state_` to `STATE_TRAJ_EXEC` on success or back to `STATE_IDLE` on failure (back to `STATE_TRAJ_EXEC` for a failed advance replan, since the current trajectory is kept). Unlike in earlier versions of this file, this round-trip is no longer inert scaffolding — it is the mechanism that actually drives every replan.

## 3. Control flow and state machine

### Data flow

Everything is driven from `timerReplanner()`; the subscriber callbacks only feed state into it:

```text
callbackOctomap()    ── merges map into octree_, sets map_ready_ ─┐
callbackFrontiers()  ── caches viewpoints, sets tsp_ready_ ───────┤ (gates)
callbackPrecomputedPath() ── stores skeleton_estimator path ──────┘ (read by makePathPrecomputed())
                                                                  ▼
timerReplanner()  [timer_rates/fast, 20 Hz]
├─ exploration_finished_ ───────────────────► return (every tick)
├─ getCurrentStateAndPrediction()  (getPosition(), getFullStatePrediction())
├─ checkStuck()  (once per tick)
├─ (no frontiers left || no_suitable_frontiers_) && !precomputed_has_targets_ && stuck ─► exploration_finished_ = true, publish ~exploration_finished_out true
├─ STATE_IDLE ──────────────────────────────► requestReplan()
└─ STATE_TRAJ_EXEC
   ├─ goalWithinLatency()        → true ───► requestReplan()
   ├─ checkTrajectoryCollision() → true ───► requestReplan()
   ├─ stuck                      → true ───► changeState(STATE_IDLE)  (replan on a later tick)
   └─ following_precomputed_ && pre_mode_ == FOLLOW && precomputed/replan_period elapsed ─► requestReplan(true)  (advance replan)

requestReplan()  [cooldown: planning/replan_request_cooldown]
└─ STATE_PATH_PLANNING, blocking self-call ~replan_request_out → ~replan_request_in
   └─ callbackReplanRequest()
      └─ pathAndTrajectory()
         ├─ makePath()
         │  ├─ getCurrentStateAndPrediction()
         │  ├─ compensateLatency()  (start_coord/velocity advanced along the prediction)
         │  ├─ [advance_replan_] makePathPrecomputed(.., true) only, return its result (no TSP fallback, goal_ untouched)
         │  ├─ makePathPrecomputed() (if precomputed/enabled)   (PRE_PATH → following_precomputed_, skip the TSP pipeline below; PRE_NONE → fall through)
         │  │   ├─ resamplePath() → labelSamples()
         │  │   ├─ [pre_mode_ == FOLLOW] planFollow()   (path samples → path_, cyan rays; no path_planner)
         │  │   └─ planGoto() → findEntries() → planEntry() → path_planner   (→ enterFollow() → planFollow() once at the anchor)
         │  ├─ solveTsp()           → tsp_solver ~set_start / ~solve       (global viewpoint tour)
         │  ├─ visualizeGlobalPath()                                       (green rays, queued)
         │  ├─ refineLocalTour()    (if local_refinement/enabled)          (orange rays, queued)
         │  ├─ buildLocalPath()     → path_planner ~find_simplified_path   (per tour segment)
         │  └─ finalizePath()       → path_, goal_, next_goal_
         ├─ draw path_ (magenta), publish bv_path_
         ├─ makeTrajectory(path_)   → trajectory_generation/get_path
         └─ publishTrajectory()     → control_manager/trajectory_reference (fly_now)
   └─ success → STATE_TRAJ_EXEC (re-arm checkStuck()), failure → STATE_IDLE (STATE_TRAJ_EXEC for an advance replan)
```

`finalizePath()` sets `goal_` to the first tour viewpoint and `next_goal_` to the end of the committed path; `goalWithinLatency()` watches those two points, closing the loop. If `makePath()` fails after it has already reset `goal_` to the current position, `goalWithinLatency()` fires again on the next tick, so a failed replan is retried (subject to the cooldown) both from `STATE_IDLE` and from `STATE_TRAJ_EXEC`.

### State machine

`Explorer` declares a `State_t` enum (`STATE_IDLE, STATE_PATH_PLANNING, STATE_TRAJ_EXEC, STATE_COLLISION`) and a `changeState()` helper that logs and sets the `state_` member. `state_` is driven entirely from `timerReplanner()`/`requestReplan()`:

- `STATE_IDLE` — the initial value, set once in `onInit()`. `timerReplanner()` re-enters it whenever `requestReplan()`'s self-call to `~replan_request` fails (except for an advance replan), and `checkStuck()` forces it back to `STATE_IDLE` (from `STATE_TRAJ_EXEC`) if the UAV hasn't moved more than `planning/stuck_distance` in `planning/stuck_duration` seconds. While `state_ == STATE_IDLE`, `timerReplanner()` calls `requestReplan()` on every tick (subject to the cooldown), i.e. it keeps retrying until a replan succeeds.
- `STATE_PATH_PLANNING` — set by `requestReplan()` immediately before it makes the blocking `~replan_request` service call; used only as a transient marker while that call is in flight.
- `STATE_TRAJ_EXEC` — set by `requestReplan()` once the `~replan_request` call returns `success = true` (i.e. `pathAndTrajectory()`/`makePath()` produced and published a trajectory). While in this state, `timerReplanner()` runs its full per-tick logic: `goalWithinLatency()`, `checkTrajectoryCollision()`, the stuck-forces-IDLE check (using the `checkStuck()` result computed earlier in the same tick), and the periodic advance replan while following the precomputed path in FOLLOW mode.

Precomputed path following has its own sub-state, `pre_mode_` (`PRE_MODE_NONE`/`PRE_MODE_GOTO`/`PRE_MODE_FOLLOW`), driven from `makePathPrecomputed()`: GOTO flies to an entry anchor via `path_planner`, FOLLOW flies the path itself; a finished FOLLOW segment returns to GOTO for the next start, and any failure to find an entry drops to NONE (frontier exploration).
- `STATE_COLLISION` — declared in the enum but never assigned anywhere in the current code; dead state. (Collision detection instead routes through `checkTrajectoryCollision()` triggering a normal `requestReplan()`, not a dedicated collision state.)

`timerReplanner()` short-circuits with `if (state_ != STATE_TRAJ_EXEC) return;` after the `STATE_IDLE` branch, so its `goalWithinLatency()`/`checkTrajectoryCollision()` checks and the stuck-forces-IDLE logic only run once a trajectory is actually being executed (`checkStuck()` itself runs every tick, for the end-of-exploration check). Once `exploration_finished_` is set (sticky), the timer keeps running but returns early on every tick. Note that the `inline` `_state_names_` string array (in `explorer.hpp`) used for logging in `changeState()` still has 7 entries (`"IDLE", "STATE_PATH_PLANNING", "STATE_TRAJ_EXEC", "STATE_COLLISION", "TSP_UPDATED", "WAITING", "FLYING"`) left over from an older 7-value enum, even though `State_t` now only has 4 values (indices 0-3); the trailing three entries are unused but harmless since `state_` never takes a value outside 0-3.

## 4. Important functions

(all methods of `explorer::Explorer`, declared in `include/explorer/explorer.hpp`; the defining file is given per function — see also section 5)

- **`onInit()`** (`explorer_nodelet.cpp`) — nodelet entry point; loads parameters from `explorer.yaml`, plus `zone_x`/`zone_y`/`zone_z` (from `world_info.yaml`) and `zone/global/floor`, from which it builds `flight_zone_` (`explorer_utils::AABB`, x/y centred on the origin, z from the floor to floor + `zone_z`; the same AABB as `path_planner`'s), sets up subscribers/publishers (publishing `false` on the latched `~exploration_finished_out`)/service clients, the `~replan_request_in` service server, starts `timer_main_`/`timer_replanner_`, and sets `state_` to `STATE_IDLE`. `timer_path_` is declared but its `createTimer()` call and the `timerPath()` method itself are both commented out — that timer no longer exists; its old responsibilities were folded into `pathAndTrajectory()`, which is now invoked from `callbackReplanRequest()` instead of its own timer. `timer_rates/path` is still loaded into `_rate_path_timer_` here, but with `timer_path_` never created that parameter has no effect at runtime.
- **`timerMain()`** (`replanner.cpp`) — periodic main-loop timer (`timer_rates/main`); still a no-op placeholder once the map is ready.
- **`timerReplanner()`** (`replanner.cpp`) — periodic timer (`timer_rates/fast` in `explorer.yaml`, default 20 Hz) and the actual driver of the whole replanning loop. Guards on `is_initialized_`/`map_ready_`/`tsp_ready_`, and returns early if `exploration_finished_` is set. Then fetches `getCurrentStateAndPrediction()` and calls `checkStuck()` once. If (`had_frontiers_ && num_frontiers_ == 0`, or the last `finalizePath()` found no suitable frontiers) and `!precomputed_has_targets_` and the UAV is stuck, logs `END OF EXPLORATION`, sets the sticky `exploration_finished_`, publishes `true` on `~exploration_finished_out` and returns. If `state_ == STATE_IDLE`, calls `requestReplan()` and returns (so it keeps retrying every tick, subject to the cooldown, until a replan succeeds). Otherwise it returns immediately unless `state_ == STATE_TRAJ_EXEC`; while executing a trajectory, in order: if `goalWithinLatency()` is true, calls `requestReplan()` and returns; else if `checkTrajectoryCollision()` is true, calls `requestReplan()` and returns; else if the stuck result is true, forces `changeState(STATE_IDLE)` (which causes `requestReplan()` to be retried on the next tick); else, if `following_precomputed_`, `pre_mode_ == PRE_MODE_FOLLOW` and at least `precomputed/replan_period` s have passed since `last_replan_request_time_`, calls `requestReplan(true)`.
- **`requestReplan(bool advance_only = false)`** (`replanner.cpp`) — no-ops if called again within `planning/replan_request_cooldown` seconds of its last actual call (guards against being hammered by `timerReplanner()`'s fast tick while idle). Otherwise sets `state_ = STATE_PATH_PLANNING` and sets `advance_replan_ = advance_only` for the duration of the blocking `~replan_request_out` service call (a self-call to this node's own `~replan_request_in`, handled by `callbackReplanRequest()`; `makePath()` reads `advance_replan_`); on success sets `stuck_check_reset_ = true` and `state_ = STATE_TRAJ_EXEC`, on failure sets `state_ = STATE_IDLE` (`STATE_TRAJ_EXEC` if `advance_only`, as the current trajectory is kept).
- **`pathAndTrajectory()`** (`replanner.cpp`) — runs one full replan-and-publish cycle: calls `makePath()` (returns `false` if it didn't produce a new path); draws the resulting `path_` as magenta debug rays on `bv_path_`, publishes and clears that buffer; calls `makeTrajectory(path_)` (returns `false` on `std::nullopt`); calls `publishTrajectory()` with the result (returns `false` on failure); folds the measured cycle duration (from before `makePath()` to the trajectory being published) into `latency_estimate_` as an exponential moving average (`est = alpha*dt + (1-alpha)*est`, `alpha = planning/latency_ema_alpha`; skipped when `planning/latency_compensation <= 0`), logs the replan time and current latency estimate, and returns `true`. Called only from `callbackReplanRequest()`. This is the successor to the old, now-removed `timerPath()` — the logic is the same, just invoked synchronously from the `~replan_request_in` handler instead of its own timer.
- **`callbackOctomap()`** (`callbacks.cpp`) — merges the incoming local-zone octomap into the persistent global `octree_` under `mutex_octree_` (the first message seeds `octree_`; later ones are `expand()`ed and fused with `explorer_utils::mergeInto`, the same local-to-global fusion `frontier_detector` and `path_planner` use), latches the map frame onto `bv_path_` once, and sets `map_ready_`; does *not* extract frontiers (that happens out-of-process in `frontier_detector`).
- **`callbackFrontiers()`** (`callbacks.cpp`) — replaces `frontier_viewpoints_` (frontier id → viewpoints with coverage, guarded by `mutex_frontier_viewpoints_`) with the latest message's contents, records `num_frontiers_` (the message's frontier count) and sets `had_frontiers_` once any non-empty message is seen, and sets `tsp_ready_`, which (once set by the first frontier message) un-gates `timerReplanner()`; it is never cleared, so it does not schedule individual re-solves. Roadmap updates from frontiers happen internally in `path_planner`, not here.
- **`callbackReplanRequest()`** (`replanner.cpp`) — handler for `~replan_request_in`; calls `pathAndTrajectory()` and returns its result in `response.success` (`response.message` is unconditionally `"acknowledged"`). This is the sole entry point that actually triggers a replan/trajectory publish; it is only ever invoked via the self-call described above (from `requestReplan()`).
- **`callbackPrecomputedPath()`** (`callbacks.cpp`) — stores `skeleton_estimator`'s latest `PrecomputedPath` (waypoints with position/yaw, frame, `path_id`, `stable`) under `mutex_precomputed_`; the path counts as followable only if `stable`, `path_id >= 0` and non-empty. A changed `path_id` sets `precomputed_reset_`, which makes `makePathPrecomputed()` drop its committed entry and no-progress counters.
- **`makePath()`** (`frontier_path.cpp`) — the core replanning routine, a thin orchestrator over several helpers, called unconditionally (no internal collision/distance gating of its own): `getCurrentStateAndPrediction()` (abort if unavailable) → `compensateLatency()` (moves `start_coord`/`velocity` ahead along the prediction) → if `advance_replan_` is set, returns `makePathPrecomputed(.., true)`'s result right away (before touching `goal_`; never falls back to TSP; timed as `makePath/precomputed_advance`) → sets `goal_`/`current_viewpoint_` to the (compensated) `start_coord` → `makePathPrecomputed(.., false)` (only if `precomputed/enabled`; on `PRE_PATH` sets `following_precomputed_` and returns `true` immediately, on `PRE_NONE` falls through) → `disableTspGuiding()` (only if `precomputed_done_` and not yet disabled) → `solveTsp()` (abort if it fails) → `visualizeGlobalPath()` → `refineLocalTour()` (only if `local_refinement/enabled`) → `buildLocalPath()` (abort if it fails) → `finalizePath()`, whose return value is `makePath()`'s own return value (`following_precomputed_` is cleared when it succeeds). Unlike in earlier versions of this file, `makePath()` no longer calls `checkImminentCollision()` or `goalWithinLatency()` itself — the gating checks live in `timerReplanner()`, which only invokes the whole chain (via `requestReplan()`) once they've fired.
- **`makePathPrecomputed(start_coord, velocity, advance_only)`** (`precomputed_path.cpp`, as are the helpers below) — follows `skeleton_estimator`'s precomputed coverage path only where it enters unknown space (no TSP), as a GOTO/FOLLOW state machine (`pre_mode_`). Returns a `PrecomputedResult_t`: `PRE_PATH` (`path_` filled) or `PRE_NONE` (no path; `makePath()` falls back to frontier exploration, or with `advance_only` keeps the current trajectory). `PRE_NONE` is returned if the path is unstable/shorter than 2 waypoints, its frame differs from the octree frame, or no entry exists/could be planned (the mode is then reset). Otherwise `resamplePath()` and `labelSamples()` are run; then the completion check: while no sample is `LABEL_UNKNOWN` the time since that first happened is tracked in `precomputed_all_known_since_` (reset on any UNKNOWN sample or when the path is unstable), and once it reaches `precomputed/done_duration` (`_pre_done_duration_`) `precomputed_done_` (atomic) is set, `precomputed_has_targets_` cleared, the mode reset and `PRE_NONE` returned — permanently: from then on the function returns `PRE_NONE` immediately for the rest of the run (a new `path_id` does not re-enable it). Otherwise: with `advance_only` (the periodic advance replan, see `timerReplanner()`) only `planFollow(.., true)` is tried while in FOLLOW; otherwise, while in FOLLOW, `planFollow()` is tried first and, when its segment is done, the mode is reset and `planGoto()` selects the next start (at most two tries per replan: if `planGoto()` finds the UAV already at an anchor and enters FOLLOW, `planFollow()` follows immediately, and if that gets nowhere the next entry is tried). Sets `precomputed_has_targets_` (whether any entry remains after dropping no-progress ones; entries merely backing off still count), which blocks the end-of-exploration check.
- **`planGoto(samples, labels, start_coord, velocity)`** — returns `GOTO_PATH` (`path_` filled, mode GOTO), `GOTO_FOLLOW` (UAV already at an anchor, FOLLOW entered via `enterFollow()`, no `path_` yet) or `GOTO_NONE`. `findEntries()` lists the entries; those whose `entryRecord()` `no_progress` counter reached `precomputed/max_no_progress` are dropped, those still within their `retry_after` backoff are skipped for this replan. The committed entry from the previous GOTO (anchor path parameter `u` + direction in `committed_entry_`, re-located with `nearestSample()`) is advanced along its direction through the known stretch to the last KNOWN sample before unknown space, and if the UAV is within `precomputed/join_distance` of any sample of that stretch, FOLLOW is entered there. Otherwise the committed entry is tried first, then the others nearest-first to the UAV, at most `precomputed/max_entry_attempts`: an anchor within `join_distance` enters FOLLOW, else `planEntry()` plans start -> anchor through `path_planner` (a failure backs the entry off for `precomputed/failure_backoff` s; it doesn't count as no progress). On success fills `path_` (anchor's yaw as headings) and sets `goal_` = the anchor, `next_goal_` = the end of the path (so the replan triggers on approaching the anchor, which then enters FOLLOW).
- **`planFollow(samples, labels, wps, start_coord, advance_only)`** — returns `FOLLOW_PATH` or `FOLLOW_DONE`. Re-locates the UAV on the path (nearest sample in a window around the last progress `pre_progress_u_`); farther than `precomputed/off_path_distance` from it means the path is lost -> done. Walks the path ahead in `pre_dir_`, stopping at the first sample outside `flight_zone_` or with an occupied voxel within `precomputed/follow_clearance` (via `occupiedWithin`; unknown voxels are ignored, so unknown space is flown through). The samples within `precomputed/follow_horizon` become `path_` directly (points thinned by `_skip_path_point_distance_`, FC-Planner headings), `goal_` = `next_goal_` = the last point, and the walked stretch is drawn as cyan rays on `bv_path_`. The segment is done when there is no UNKNOWN sample within `precomputed/max_known_gap` of path length ahead, or the resulting path is shorter than `precomputed/min_path_length`; if (not `advance_only`) that happens with the UAV still within `min_path_length` of its entry anchor (`pre_entry_u_`), the entry's `no_progress` counter is incremented. With `advance_only` the following state is changed only by the progress update.
- **`disableTspGuiding()`** — calls `sc_tsp_set_guiding_` (`std_srvs/SetBool`, `data=false`); returns `true` on success, otherwise warns and returns `false` (`makePath()` keeps `tsp_guiding_disabled_` unset and retries on the next replan).
- **`enterFollow(entry_u, progress_u, dir)`** — sets `pre_mode_ = PRE_MODE_FOLLOW` with `pre_entry_u_`, `pre_progress_u_`, `pre_dir_` and clears `committed_entry_`.
- **`resetPrecomputedMode()`** — sets `pre_mode_ = PRE_MODE_NONE` and clears `committed_entry_`.
- **`occupiedOnlyChecks()`** (inline) — true while `following_precomputed_` and `pre_mode_ == PRE_MODE_FOLLOW`; `checkTrajectoryCollision()` and `compensateLatency()` then consider only occupied voxels (via the static `occupiedNear(tree, c, r)`, caller holds `mutex_octree_`) instead of requiring free space, since FOLLOW flies through unknown space.
- **`PathSample_t` / `resamplePath(wps)`** — `resamplePath()` inserts samples every `precomputed/sample_step` along each segment of the precomputed waypoints; a `PathSample_t` holds `position`, `yaw` (of the waypoint its segment leads to), `wp` (index of the waypoint it was resampled from) and `u` (path parameter: `wp` + fraction along the segment, unaffected by `skeleton_estimator`'s transform drift).
- **`nearestSample(samples, u)`** (static) — index of the sample whose `u` is closest to the given one (samples are sorted by `u`), `-1` if there are none.
- **`labelSamples(samples)`** — labels each sample with `path_planner`'s own reachability test: KNOWN (`LABEL_KNOWN`) if the whole `precomputed/clearance` ball around it is known free; OCCUPIED if it or an occupied voxel within the ball is occupied; UNKNOWN if it or an unknown voxel (and no occupied one) within the ball is unknown; OUTSIDE if it lies outside `flight_zone_` (`path_planner` has no roadmap nodes there) or on segment 0 (`wp == 0`). `isSkippedLabel()` (OCCUPIED or OUTSIDE) is the predicate used wherever such samples are ignored. The per-voxel state lookup (`voxelState()`, memoized FREE/UNKNOWN/OCCUPIED), the clearance-ball sweep (`clearanceState()`) and the occupied-only sweep (`occupiedWithin()`, used by `planFollow()` and `occupiedNear()`) are file-local helpers in an anonymous namespace of `precomputed_path.cpp`.
- **`nextFollowed(labels, i, dir)`** (static) — index of the next sample from `i` in direction `dir` that is not OUTSIDE/OCCUPIED, `-1` if none.
- **`findEntries(labels)`** (static) — every KNOWN sample whose next followed sample (`nextFollowed()`) in a direction is UNKNOWN is an entry `{index, direction}`, once per direction (`+1`/`-1` along the tour).
- **`entryRecord(samples, i, dir)`** — returns an `EntryRecord_t&` for the entry anchored at sample `i` in direction `dir` (in `entry_records_`, keyed by path parameter `u` and `dir`, matched within one sample via `nearestSample()` since sample indices and positions shift with the path's transform; created zeroed on first use). It holds the `no_progress` counter and a `ros::Time retry_after` (planning-failure backoff deadline).
- **`planEntry(start_coord, velocity, target, yaw, path, headings)`** — plans start → target (the anchor) through `path_planner` only; the path counts only if it ends within `precomputed/reach_tolerance` of the target (`path_planner` snaps goals to the nearest roadmap node and reports success even when the goal itself isn't reachable). Path points get the given `yaw` (the anchor's) as `headings`. Returns `false` if the target can't be reached or the path ends within `precomputed/min_path_length` of the start (it would leave the UAV hovering).
- **`getCurrentStateAndPrediction(start_coord, prediction, velocity)`** (`monitoring.cpp`, as are `compensateLatency`, `goalWithinLatency`, `checkStuck`, `checkTrajectoryCollision`, `getFullStatePrediction`, `getPosition`) — fetches the current UAV position via `getPosition()` and the MPC full-state prediction via `getFullStatePrediction()`, deriving `start_coord`/`prediction`/`velocity`; returns `false` with a throttled warning if either is unavailable. Called from both `makePath()` and `timerReplanner()`.
- **`compensateLatency(prediction, start_coord, velocity)`** — the UAV keeps flying the old trajectory while `makePath()` runs, so this advances `start_coord`/`velocity` along the MPC full-state prediction by `2*latency_estimate_` seconds (the same horizon `goalWithinLatency()` triggers the replan at, minus its one-tick margin; `latency_estimate_` is an adaptive estimate of the replan latency, seeded in `onInit()` from `planning/latency_compensation` and updated in `pathAndTrajectory()`; measured from `prediction.stamps[0]`), stopping early at the last sample that is still free space per `explorer_utils::isFreeSpace(p, _flight_free_distance_, *octree_)` (holds `mutex_octree_`; in precomputed FOLLOW only occupied voxels within `_flight_free_distance_ / 2` stop it, see `occupiedOnlyChecks()`). The compensated start is therefore used as the TSP start (`current_viewpoint_`), the reset `goal_`, and the start of the first `path_planner` segment, which avoids backtracking to points the UAV has already passed. No-op if `planning/latency_compensation` is `<= 0` (which disables compensation entirely), `octree_` is null, or `stamps`/`velocity` sizes don't match `position`. Called from `makePath()` only.
- **`checkImminentCollision(start_coord, prediction)`** — walks the MPC prediction's position samples against `octree_`, holding `mutex_octree_` for the whole check; if any sample is not free space (per `_flight_free_distance_`), sets `path_.points = {start_coord, last_free_point_}`, bumps `path_.id`, sets `goal_` to the brake point, sets `braking_ = true`, and returns `true` (an emergency brake path). Otherwise updates `last_free_point_` and returns `false`. **Dead code**: declared in `explorer.hpp` but not defined in any of the compiled `.cpp` files and not called from anywhere.
- **`goalWithinLatency(prediction)`** — for each of `goal_` (the first tour viewpoint) and `next_goal_` (the end of `path_`), finds the prediction's closest approach to it over the full horizon and takes the time offset (from the first stamp) of the first sample within `planning/goal_reached_tolerance` (`_goal_reached_tolerance_`) of that closest distance; returns `true` once the earlier of the two times is `<= 2*latency_estimate_ + 1/timer_rates/fast`, so the replan starts with a margin of one extra latency before the goal. A goal beyond the horizon maps to the last sample, i.e. not yet due. Returns `false` if the prediction is empty or its `stamps` size doesn't match `position`. Called only from `timerReplanner()`.
- **`checkStuck(start_coord)`** — stuck-detection helper, called once per `timerReplanner()` tick; its result feeds both the end-of-exploration check and the forced-IDLE logic in `STATE_TRAJ_EXEC` (same `planning/stuck_distance`/`planning/stuck_duration` params for both). Tracks `last_moved_position_`/`last_moved_time_`; whenever the UAV has moved more than `planning/stuck_distance` since the tracked position (or `stuck_check_reset_` is set, e.g. right after a successful `requestReplan()`), it re-arms the tracker and returns `false`; otherwise it returns `true` once `planning/stuck_duration` seconds have elapsed without that much movement, signalling `timerReplanner()` to force `state_` back to `STATE_IDLE` (or, with no frontiers left, to declare exploration finished).
- **`solveTsp(velocity, glob_path, tour_ids)`** (`frontier_path.cpp`, as are `buildLocalPath`, `findSimplifiedPath`, `randomStepPath`, `finalizePath`) — calls `tsp_solver`'s `~set_start_out` (with `current_viewpoint_`) then `~solve_out` (with `velocity`) services; fills `glob_path` and the parallel frontier ids `tour_ids` (the response's `ids`) and returns `false` if either call/response fails or the returned tour has `size() <= 1`.
- **`refineLocalTour(start_coord, velocity, glob_path, tour_ids)`** (`local_refinement.cpp`) — local viewpoint refinement. Takes the consecutive tour clusters after the start whose tour viewpoint is within `local_refinement/radius` of `start_coord` (at most `max_clusters`, stopping at the first one missing from `frontier_viewpoints_`) and re-picks one viewpoint per cluster from its top `max_viewpoints` by coverage (the tour's own viewpoint is always candidate 0). The candidates form a layered DAG start → cluster 1 → … → cluster N → next tour point (fixed anchor), solved by DP over the layers; cost is the sum of Euclidean edge lengths plus `w_consistency` × angle between current velocity and the first edge (only when speed > 0.2 m/s) minus `w_coverage` × coverage normalized per layer. Rewrites the chosen viewpoints into `glob_path` in place and queues the refined segment as orange rays on `bv_path_`. Skips with a warning if `tour_ids` and `glob_path` sizes differ.
- **`visualizeGlobalPath(glob_path)`** (`callbacks.cpp`) — draws the freshly solved global TSP tour as green debug rays on `bv_path_` (buffer is not published/cleared here — that happens together with the local path rays in `pathAndTrajectory()`).
- **`buildLocalPath(start_coord, glob_path, velocity, path, sub_global_path)`** — walks forward through `glob_path`, skipping points closer than `_skip_path_point_distance_` to the last accepted `sub_global_path` point, and for each accepted sub-segment calls `findSimplifiedPath()` (the `path_planner` `~find_simplified_path_out` service) to get a simplified sub-path, appending points more than `_skip_path_point_distance_` from the current `path` tail. Only the first segment is planned with the UAV's current `velocity`; later ones get zero velocity. Stops once `path` extends `planning/max_length_after_first_viewpoint` (`_max_length_after_first_viewpoint_`) of arc length past the first tour viewpoint — cutting the overshooting edge exactly at that length, to keep the trajectory generation request short — or when the tour runs out of distinct points. On a `~find_simplified_path_out` call/response failure it returns `false` — except as a fail-safe: after `kMaxTempPathFailures` (10) consecutive failures (counter `temp_path_fail_count_`, reset on any success) it instead returns `true` with `path`/`sub_global_path` set by `randomStepPath()` (a 1 m step in a random direction from `start_coord`), to escape a planner deadlock.
- **`findSimplifiedPath(start, goal, velocity, segment)`** — wraps the `path_planner` `~find_simplified_path_out` call for a single start/goal pair with the given initial velocity; fills `segment` with the returned points and returns `false` if the call or the planner's `success` flag fails. Called from `buildLocalPath()`.
- **`randomStepPath(start_coord, path, sub_global_path)`** — fail-safe for `buildLocalPath()`: sets both `path` and `sub_global_path` to `{start_coord, start_coord + 1 m in a uniformly random direction}` (drawn with `rng_`).
- **`finalizePath(path, sub_global_path)`** — clears `path_.headings` (the TSP pipeline leaves heading to the trajectory generator), drops the leading point of `path` (the UAV's current, already-occupied position), commits the rest into `path_.points`, bumps `path_.id`; if the result is non-empty, updates `goal_`/`next_goal_`, and returns `true`; otherwise warns "no suitable frontiers" and returns `false`.
- **`checkTrajectoryCollision(start_coord, prediction)`** — checks the given MPC prediction's position samples against `octree_`, holding `mutex_octree_` for the whole check (per `_flight_free_distance_`) and returns `true` if any sample is occupied (stops at the first occupied sample found); in precomputed FOLLOW (`occupiedOnlyChecks()`) only occupied voxels within `_flight_free_distance_ / 2` count, unknown space is flown through. Called live from `timerReplanner()` on every tick while `state_ == STATE_TRAJ_EXEC`; its parameters are passed in by the caller (`start_coord` is unused). This is a separate check from `checkImminentCollision()` (see above, now itself dead), which additionally mutated `path_`/`goal_`/`braking_`/`last_free_point_`; `checkTrajectoryCollision()` only reports true/false and mutates no planning state itself.
- **`makeTrajectory(const Path_t& path)`** (`trajectory.cpp`, as is `publishTrajectory`) — converts the given `path` (points, `path.id` unused here) into an `mrs_msgs::TrajectoryReference` via the `~trajectory_generation_out` service (when `path.headings` has one entry per point, as filled by precomputed path following, it sends them with `use_heading=true`, `relax_heading=false`) and returns it (or `std::nullopt` on a failed/unsuccessful service call). `pathAndTrajectory()` calls it with `path_` after `makePath()` returns.
- **`publishTrajectory(const mrs_msgs::TrajectoryReference& trajectory, int id)`** — publishes a trajectory previously produced by `makeTrajectory()` via the `~trajectory_reference_out` service, setting `fly_now=true` and `input_id=id`; returns `false` on a failed/unsuccessful service call. `pathAndTrajectory()` calls it with the result of `makeTrajectory()` and `path_.id`.
- **`getFullStatePrediction()`** — returns the tracker's full-state MPC prediction (or `nullopt` if diagnostics/tracker_cmd are stale (>2s) or no frame transform is available), delegating to `explorer_utils::getFullStatePrediction`.
- **`getPosition()`** — returns the current UAV position in the octree frame, delegating to `explorer_utils::getPosition`.
- **`msgToMap()`** (`callbacks.cpp`) — deserializes an `octomap_msgs/Octomap` (binary or full) into an `OcTree_t`.
- **`changeState()`** (`replanner.cpp`) — logs and sets `state_`; see State machine section above. Called from `requestReplan()` (`STATE_PATH_PLANNING`, `STATE_TRAJ_EXEC`, `STATE_IDLE`) and `timerReplanner()` (`STATE_IDLE`, via `checkStuck()`).
- **`controlManagerDiagCallback()`** (`callbacks.cpp`) — diagnostics callback; currently a no-op besides the init guard.
- **`timeoutTrackerCmd()` / `timeoutOctomap()`** (`callbacks.cpp`) — `SubscribeHandler` timeout callbacks; log a throttled warning when the respective topic goes stale.

## 6. Dependencies

From `package.xml`/`CMakeLists.txt` (build-time, catkin). The package defines no `msg`/`srv`/`action` files of its own (the former `srv/Path.srv` and its `message_generation`/`message_runtime` dependencies were removed along with the dead `~get_path_in` service):

- `mrs_lib`, `mrs_msgs`, `mrs_modules_msgs` — MRS UAV stack core: `BatchVisualizer`, `ParamLoader`, `SubscribeHandler`, `Transformer`, `ServiceClientHandler`, and message types (`TrackerCommand`, `ControlManagerDiagnostics`, `TrajectoryReference*`, `GetPathSrv`, etc.)
- `std_srvs` — `std_srvs::Trigger`, used for both the `~replan_request_in` service server (`ss_replan_request_`/`callbackReplanRequest`) and the `~replan_request_out` service client (`sc_replan_request_`, called from `requestReplan()`, itself called from `timerReplanner()`)
- `mrs_subt_planning_lib`, `mrs_octomap_tools` — external MRS repos; `mrs_octomap_tools/octomap_methods.h` is included only by `src/explorer_nodelet.cpp` (it defines non-inline `checkType<>` specializations, so a second translation unit including it breaks linking); nothing in the package uses it
- `octomap_msgs`, `octomap_ros`, plus `find_package(octomap REQUIRED)` and `find_package(dynamicEDT3D REQUIRED)` — octomap representation/conversion
- `nodelet`, `roscpp`, `rospy`, `pluginlib` (via `PLUGINLIB_EXPORT_CLASS`) — nodelet plumbing
- `nav_msgs`, `std_msgs`, `geometry_msgs`, `visualization_msgs`, `sensor_msgs` — standard ROS message types
- `Eigen3` (`find_package(Eigen3 REQUIRED)`) — used via `mrs_lib::geometry::Ray`/`BatchVisualizer` calls in the Explorer sources
- `explorer_utils` — this project's own shared geometry/octomap helper library (including `TimingPublisher`); the Explorer sources fully qualify every call with the `explorer_utils::` prefix (`isFreeSpace`, `getPosition`, `getFullStatePrediction`, etc.) — `Explorer::getPosition()`/`Explorer::getFullStatePrediction()` are now both thin delegators to their `explorer_utils` counterparts
- `frontier_detector` — declared as a build dependency for its `FrontierArray` message type, consumed on `~frontiers_in`
- `skeleton_estimator` — build/run dependency for its `PrecomputedPath` message type, consumed on `~precomputed_path_in`

Runtime-only (not build dependencies, but required at runtime for `Explorer` to function — separate standalone nodelets started elsewhere, e.g. from `tmux/session.yml`):

- `worlds/<world_name>/world_info.yaml` — `zone_x`/`zone_y`/`zone_z` are read in `onInit()`; passed to `explorer.launch` as `world_info_file_config` (`tmux/session.yml` wires `${WORLDS_DIR}/${WORLD_NAME}/world_info.yaml`) and loaded with `<rosparam>`

- `tsp_solver` — provides the `~set_start_out`/`~solve_out` services `solveTsp()` calls and the `set_guiding` service `disableTspGuiding()` calls (also a build dependency, for the `SetStart`/`Solve` service message types)
- `path_planner` — provides the `~find_simplified_path_out` service `buildLocalPath()` calls (also a build dependency, for the `FindSimplifiedPath` service message type)
- `skeleton_estimator` — publishes `skeleton_estimator/precomputed_path`; optional, without a stable path `makePath()` uses the TSP pipeline only
- `frontier_detector` — the actual `FrontierDetectorNodelet` nodelet must be running to publish `frontier_detector/frontiers`, which `Explorer` consumes as a trigger signal and for its per-frontier viewpoint cache (the same topic is independently consumed by `tsp_solver` and `path_planner` for their own internal state)

`~replan_request_in`/`~replan_request_out` are both remapped to the same `~replan_request` topic in `explorer.launch`, so the `std_srvs::Trigger` request/response round-trips entirely within this node today — it is not currently a dependency edge to or from any other package.
